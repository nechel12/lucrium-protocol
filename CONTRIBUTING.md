# Как помочь

Проект в стадии разработки и тестирования. Этот репозиторий — контракт
(модели протокола и SDK), и помощь здесь особенно заметна: неверное поле или
неполный гайд превращаются в баги и в воркере, и в панели, и у авторов плагинов.

## Самый нужный вклад — тестирование

1. **Написать плагин по гайду**
   [Как писать плагины](packages/lucrium-plugin-sdk/docs/writing-plugins.md)
   и рассказать, где шаг за шагом пришлось импровизировать. Гайд считается
   дефектным, если рабочий плагин по нему не собирается с первого прогона.
2. **Проверить примеры** (`examples/auto-reply`, `examples/webhook-forwarder`):
   запустить через `lucrium_plugin_sdk.testing`, добавить недостающий случай.
3. **Погонять контракты на живом воркере**: установка zip-плагина, форма настроек
   из JSON Schema, `ctx.http` при `network = true`, отказ без разрешения,
   `ctx.storage` под нагрузкой. Найденное оформлять issue с версией (`v0.1.3`
   или коммит), копией манифеста и схемы, текстом ошибки.

**Тестовые учётные записи площадок.** Плагин, получивший доступ к сессии,
способен двигать реальные заказы и деньги — для экспериментов нужны
тестовые магазины.

## Если правите код

```bash
uv sync
uv run pytest
uv run ruff check packages examples
uv run ruff format --check packages examples
uv run mypy packages examples     # strict
```

- `filterwarnings = ["error"]`: варнинг в тесте — это упавший тест.
- Любое изменение модели протокола или контракта SDK обязано быть
  подкрепленным тестом **и** правкой [docs/protocol.md](docs/protocol.md) /
  гайда по плагинам: документация — часть контракта.
- Оба пакета версионируются вместе, номер совпадает с тегом (`v0.1.3`).
  Релизные теги подписываются, детали — в [SECURITY.md](SECURITY.md).
- История в `main` линейная: PR ведётся на rebase.
- Совместимость panel ↔ worker по умолчанию не сохраняется (до 1.0 можно ломать),
  но такие правки фиксируются в описании PR, потому что задевают соседние
  репозитории.

## Чего пока не нужно

Новых форматов доставки и лицензии «под магазин» (v2): они уже заложены в
моделях, и параллельные реализации сейчас мешают. Для обсуждения направления —
сначала issue.
